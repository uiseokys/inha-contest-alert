# v3 변경 범위와 실행 기록

## 사용자 요구
첨부 SKILL.md / DESIGN.md를 디자인 기준으로 적용하고, 정오 알림과 페이지에 어제 대비 새로 확인한 공고 수를 표시한다. 무료 구성, 기존 수집기, 일일 알림 및 개인 ntfy Secret 분리는 유지한다.

## 결정
- 제공 문서는 엘리스 문서 사이트를 추정한 토큰 지침이며 완성 화면 캡처가 아니다. 엘리스 로고/브랜드를 복제하지 않고 기존 제품 이름을 유지한다.
- 검정 surface.base에는 흰 text.tertiary를 사용한다. 어두운 primary 텍스트는 밝은 content 표면에서 사용한다. 추가 역할 토큰과 공간 배수는 DESIGN_APPLICATION.md에 구분해 기록한다.
- 어제의 마지막 저장 목록과 오늘의 최근 수집 목록을 비교한다. 마감으로 목록 표시 건수가 줄어도 신규 건수에서 차감하지 않는다.
- 첫 실행/v2 업데이트 직후 기준 없음은 0이 아닌 비교 준비 중이다. 전날 수집이 없으면 최근 기록 날짜를 명시하고 어제 대비라고 부르지 않는다.
- 신규 출처의 최초 적재와 전날 수집 실패 출처의 추가 발견은 신규 확정 집계와 분리한다. 공고 주소 기준이며 출처가 다른 동일 대회의 의미 기반 통합은 하지 않는다.
- 알림 전송 커서는 별도로 유지한다. 어제 대비 통계와 지난 알림 이후 미전달 공고는 혼동하지 않고 각각 표시한다.
- 기존 state.json / config.json / workflow / Secrets를 변경 없이 유지하는 업데이트 ZIP을 제공한다. 스냅샷은 collect 때 기존 state에 추가한다.

## 실행 순서
1. 기존 67개 테스트 실행 (2026-09-22: 통과).
2. 일별 비교 실패 테스트 작성 → 수집/알림/공개 데이터에 연결 → 전체 테스트.
3. 지침 기반 HTML/CSS와 동일 비교값을 사용하는 UI 구현 → 화면/키보드/긴 내용/빈 상태 검증.
4. 안내서, 디자인 적용 문서, 검증 보고서, 실제 데이터가 없는 배포본과 분리한 가상 미리보기 생성.
5. 전체/업데이트 ZIP 재압축 → 압축 해제 후 재검증. 배포/휴대폰 수신은 수행하지 않음.

## 확인할 실패 상황
시간대 날짜 경계, 첫 적재, 전날 누락, 같은 날 여러 번 실행, 출처 부분/전체 실패, 마감된 신규 공고, 새 출처 추가, 기존 알림 재실행 억제, 공개 데이터에 Secret/알림 선점 내역 노출, 320px 화면과 긴 한국어·URL, 링크의 설명과 키보드 focus.
