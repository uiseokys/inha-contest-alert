## 1순위 — 시간·상태·버전

한국시간 정오, 오늘 마감 시각 전/동일/후, 오늘 시작 전, 시각 미확인, 날짜 충돌, 명시적 해외 시간대의 날짜 경계, 잘못된 날짜를 검사했습니다. 알려진 시각과 같은 날의 마감 내림차순을 반영하며, 날짜만 있는 마감에 임의 23:59를 넣지 않습니다. 정오 예약 메시지의 마감 임박 목록도 수집 시각이 아닌 예정된 정오를 기준으로 계산합니다.

코드 지문에는 Python·웹·workflow가 포함됩니다. 실제 체크아웃 커밋, 수집 시도/부분/완전 성공, ntfy reserved/accepted/failed를 안전한 필드만 공개합니다. 토픽·응답 본문·임의 private 필드·수동 보정의 자동 원본 백업이 공개 JSON에 누출되지 않는지 검사했습니다. 수집 오류 시 이전 정상 데이터와 기존 알림 기록을 보존하는 CLI·workflow 구성을 확인했습니다.

## 2순위 — 날짜 품질

참가 신청기간과 장학금/환불/이전 일정의 문맥 분리, 빈 일정 제목, 진짜 여러 트랙 충돌을 검사했습니다. 저장된 관련 공고 전체와 이번 실행의 상세 시도·날짜 확인을 분리하고, 시간 정보가 없는 이전 항목을 이번에 조회한 것처럼 세지 않습니다. 관리자 보정 포함 확인 수와 자동 확인 수도 구분합니다.

근거·확인일·사유가 없는 보정, 미래 확인일, 역전된 기간, 날짜 변경 후 옛 시각 상속을 거부/정리합니다. 보정 제거 시 자동값 복원, 보정 후 자동 원문 변경 시 재검토 표시를 검사했습니다. 진단 CLI는 상태 복사본만 사용하며 저장된 state 바이트·발송 기록을 바꾸지 않는지 검사했습니다.

## 3순위 — 대회 단위 통합과 일별 집계

공식 대회 주소 기반 통합, 같은 제목이지만 연도/차수/이름이 있는 부문이 다른 경우의 분리, 서로 다른 공식 대회 ID, 뒤늦은 그룹 통합, 옛 관심 ID 연결, 재게시 공고의 새 대회 오집계 방지를 검사했습니다. 원래 공고·전일 snapshot·알림 claims는 삭제하지 않습니다.

한국 날짜가 바뀌었을 때 오래된 ‘어제 대비’ 숫자·신규 배지·필터가 남지 않는지 검사했습니다. 마감일 변경 전후, 파서 업그레이드로 인한 추출 정정과 실제 저장 날짜 변경을 구분합니다. 원문에 공식 연장 공지가 있는지는 여전히 원문 확인이 필요합니다.

## 4순위 — 개인 탐색

기술 분야와 행사 종류의 독립 필터, 모델 탐지와 AI 영상 제작 구분, 관심 저장/해제/관심만, 검색·필터 기억, 가져오기/내보내기, 그룹 ID 별칭, 없는 과거 관심 항목의 보존, 파일 크기·개수·JSON 형식/허용 필드 검사를 수행했습니다. 관심 마감 임박, 관련성 확인 대기, 카드 상세·원문 링크, CSV도 확인했습니다.

키보드 포커스가 있는 카드가 마감 시각에 도달해도 즉시 제거하지 않고 상태를 바꾼 뒤 초점이 이동하면 목록에서 제외하는 동작을 검사했습니다. 가로 넘침·긴 제목·모바일 버튼과 상세를 확인하고 화면 이미지를 직접 검토했습니다. WCAG 전체 적합성 인증은 아닙니다.

## 브라우저 검사 환경의 중요한 제한

이 도구 환경은 localhost와 route로 응답을 주입한 URL을 포함해 브라우저 탐색 자체를 정책상 차단했습니다. 따라서 HTML을 Chromium `set_content`로 넣고 외부 요청을 차단해 DOM 기능을 검사했습니다. **설정 유지 검사는 Storage와 같은 인터페이스의 대체 저장소를 주입하고 새 문서로 옮기는 방식**입니다. 실제 GitHub Pages origin의 localStorage 지속성을 검증한 것은 아닙니다.

별도 검사는 실제 opaque origin에서 native localStorage 접근이 거부될 때 메모리 관심 저장과 경고가 작동하는지 확인했습니다. GitHub 실행 API 검사는 응답을 대체해 실패/지연/표시 불일치를 검사했으며 실제 네트워크 조회 성공을 증명하지 않습니다.

## 공개 자료 확인과 원격 검증의 구분

공개 v6 snapshot을 읽은 사실과 그 당시 저장된 7/18 마감 확인 수는 `LIVE_AUDIT_V7.md`에 분리해 기록했습니다. v7에서 확인율이 몇 % 향상됐다는 실제 측정치는 없습니다. 공개 추출 문구를 재현한 회귀 테스트는 실제 사이트 원본 HTML 전체를 다시 수집한 것과 다릅니다.

제작 컨테이너는 외부 DNS 실패로 Python 실제 수집기를 원문에 연결해 검사하지 못했습니다. 사용자 GitHub Actions에서의 실행/커밋/Pages 배포, ntfy 전송 및 휴대폰 수신은 수행하지 않았습니다. 추가한 읽기 전용 진단 workflow는 적용 후 사용자가 실행해야 GitHub 환경의 실제 결과를 얻게 됩니다.

## 검토 방식과 결정 사항

독립 검토 도구가 없어 **작성자가 구현 뒤 별도 자체 검토**를 했습니다. 중요한 문제는 먼저 실패하는 회귀 테스트로 재현하고 수정 후 전체 suite를 다시 실행했습니다. 다음 선택은 의도적인 범위입니다.

- 관심 목록은 브라우저 저장+수동 내보내기이며 자동 기기 동기화·개인화된 ntfy 알림은 아닙니다.
- 같은 대회 판정은 확실한 근거만 사용하므로 일부 중복이 남을 수 있습니다.
- 진단의 분모는 저장된 관련 공고이며 전수 수집 보장은 아닙니다. 관리자 보정과 자동 추출을 구분합니다.
- 공개 실행 API 실패는 미확인으로 남습니다. 프로그램 시작 이전의 workflow 실패는 로그에서 확인해야 합니다.
- 날짜 변경 비교는 공식 연장 사실을 보증하지 않습니다. 파서 정정은 별도로 표시합니다.
- PDF/HWP/포스터 OCR, 로그인·접근 차단 우회는 추가하지 않았습니다.

## 배포 묶음 검증

최종 ZIP을 별도 폴더에 풀어 실제로 검사했습니다. 결과는 `verification/v7/package-validation.txt`에 기록했습니다.

- 전체 ZIP: 254 Python / 24 Node 테스트 통과. 구문·사이트 생성 통과. 공고/발송 기록은 비어 있고 `demo: false`이며, 활성 수동 보정 파일과 가상 모집 공고가 없습니다.
- 업데이트 ZIP: **제공된 원본 v6**에 가상 기존 공고 2개, 알림 기록·전날 snapshot, 개인 설정/README/보정 파일 표식을 넣고 적용했습니다. 적용 직후 `data/state.json`, `config.json`, `README.md`, `overrides.json`의 바이트가 전부 동일했습니다.
- 그 복사본에서도 254 Python / 24 Node 및 구문·렌더링이 통과했습니다. 렌더링이 state를 쓰지 않음을 확인했으며, 행사 통합 시 원래 두 공고 ID·claims·전날 snapshot이 유지됐습니다. 공개 화면에는 같은 가상 대회를 한 카드로 표시했고 비공개 시험 필드가 나오지 않았습니다.
- `daily.yml`은 의도대로 교체됐고 cron과 Secret 이름이 유지됐으며 진단 workflow가 추가됐습니다. **이번 버전에서 workflow 바이트 보존을 주장하지 않습니다.**
- 두 ZIP의 CRC 검사와 폰트/바이트코드 파일 제외 검사가 통과했습니다. 이 검사에 사용한 가상 기존 상태는 배포물에 넣지 않았습니다.

실제 사용자 저장소를 바꾸거나 알림을 보낸 검사가 아닙니다.
