## 재현한 오류와 회귀 범위

게시판의 generic h1/og:title을 실제 대회명보다 우선한 문제, form 안 본문 삭제, 실제 원문의 두 자리 연도 미인식, 목록 사이트 전체를 AI 분야로 간주한 문제를 재현하고 수정했습니다.

추가 36개 테스트는 실제 제목 선택/복구, 제외 전후 ID·알림 기록 보존, 수집 실패 시 기존 기록 필터, 원문 body와 메뉴·추천·기관명·AI 사용금지 문구 구분, 일반 제목의 실제 AI 과제 확인, 공개 접수 JSON의 대상 ID/시간대 검증, 신청일과 행사일 분리, 공식 일정 링크, 다른 시각의 충돌, 새 마감일에서 이전 시각 제거를 포함합니다. 관련 없는 신규 공고가 대시보드/알림/어제 대비 집계에 들어가지 않는지도 확인합니다.

공식 접수 링크가 있는데 기존 페이지의 날짜가 완성되어 있으면 시각 보완을 건너뛰던 문제도 최종 자체 검토에서 추가 재현 후 수정했습니다. 같은 날짜에 다른 시각이 병기되면 마지막 값을 임의로 택하지 않습니다.

테스트가 먼저 실패하는 것을 확인하고 수정했습니다. 최종 검토는 작성자의 자체 검토이며 독립 검토자를 사용하지 않았습니다.

## 실행 환경 한계

제작 컨테이너의 외부 DNS/네트워크 제한으로 Python 수집기에서 실제 외부 사이트에 요청하는 종단간 테스트를 수행하지 못했습니다. 사용자의 실제 GitHub 주소/운영 state.json도 제공되지 않았습니다. 따라서 날짜 확인율이 몇 %로 올랐는지는 측정하지 않았습니다. 첫 적용 후 출처별 수집 상태와 실제 공고 원문을 비교해야 합니다.

포스터 이미지/PDF/HWP OCR, 로그인/차단 우회, 비공개 API, 유료 AI는 사용하지 않습니다. 일부 동적 구조/공개 JSON 필드/날짜 형식은 지원되지 않을 수 있습니다. 캠퍼스픽은 제목/카드 1차 필터로 본문에만 관련 표현이 있는 공고를 놓칠 수 있습니다. 관련성 검사는 규칙 기반이며 완전한 의미 이해를 보장하지 않습니다.

## 유지한 선택 및 비용

- 인하대 대표 홈페이지만 제외, 학과·센터 소스는 유지. 기존 사용자 config는 변경하지 않고 코드 기본값을 적용합니다.
- 무관/미확인 공고는 삭제하지 않고 비노출. 장점은 이력 보존이며, 관련성 재검증 전에는 실제 관련 공고도 잠시 숨겨질 수 있습니다.
- 공개 카드 제목 선별을 유지한 캠퍼스픽은 상세 요청 낭비를 줄이지만 본문에만 있는 주제를 놓칠 수 있습니다.
- 공식 일정 보완은 알려진 플랫폼의 명시된 링크 한 단계만 확인. 임의 웹검색/무제한 연결 추적을 하지 않아 일부 신청처 날짜는 미확인입니다.
- 알림 중복 방지/하루 최대 한 번 시도/정오 목표는 기존 그대로. 실제 수신과 정시는 보장하지 않습니다.

## 최종 ZIP 적용 검증

전체 ZIP을 별도의 빈 폴더에 풀어 Python 165개 테스트·JavaScript 문법·사이트 생성을 확인했습니다. 새 설치용 state에는 공고와 발송 기록이 없습니다.

업데이트 ZIP은 제공된 v4 원본의 별도 복사본에 적용했습니다. 기존 상태에 잘못된 ‘공지사항’ 제목, 관련 없는 공고, 대표 홈페이지 공고, 가상 비공개 알림 시도 표식을 넣었습니다. 사용자 config/workflow/README에도 검증용 수정 표식을 넣었습니다.

압축 적용 직후 state.json·config.json·workflow·README는 바이트 단위로 보존됐습니다. 그 복사본에서도 Python 165개 테스트·JavaScript 문법·사이트 생성이 통과했습니다. 외부 요청을 실패시키는 모의 수집 후에도 공고 ID와 알림 표식을 보존했고, 저장된 원래 제목 복구·대표 홈페이지 비활성화·무관한 공고 비노출을 확인했습니다. 가상 비공개 표식은 공개 HTML/JSON에 포함되지 않았습니다.

이 검증용 데이터는 별도의 시험 폴더에만 있습니다. 배포 ZIP의 실사용 상태나 사용자의 원격 저장소에 넣지 않았습니다. 전체 ZIP 55개 파일, 업데이트 ZIP 46개 파일이며 글꼴·비밀값·실행 캐시·Git 메타데이터는 제외했습니다.
