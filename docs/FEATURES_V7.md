# v7 기능과 의미

## 1. 정확한 시각과 실행 상태

접수 시작과 마감은 확인된 날짜·시각·시간대를 기준으로 판단합니다. 시각이 없는 날짜는 추측하지 않습니다. 명시적 종료 상태와 충돌·미확인 기간을 별도로 처리합니다. 한국시간 기준 일별 비교와 D-day는 기기 표시 시간대에 좌우되지 않도록 구성했습니다. 현재 시계는 기기 시계를 사용하므로 기기 시계 자체가 틀리면 영향을 받습니다.

화면에는 앱 버전, Python·웹·workflow를 포함한 코드 지문, 실행 커밋/링크, 마지막 수집 시도·사용 가능한 수집·완전 수집, 현재 생성 시각, ntfy 전송 시도 상태를 표시합니다. 부분 성공을 모든 출처 성공으로 표현하지 않습니다. GitHub 공개 실행 API가 차단되거나 제한되면 최근 실행을 확인하지 못했다고 표시합니다. 초기 설치/의존성 오류 등 프로그램이 시작하기 전 실패는 상태 파일에 쓰지 못할 수 있으므로 실행 로그와 공개 실행 조회를 함께 사용합니다.

## 2. 날짜 품질 진단과 보정

`site/quality.json`과 `quality.md`의 분모는 **저장된 관련 공고 주소 수(이미 마감된 공고 포함)**입니다. 행사 단위 카드 수 또는 전체 인터넷 공고 수가 아닙니다. 이번 실행 상세 조회·날짜 추출, 과거 날짜 유지, 수동 보정, 원문 재검토 필요를 분리합니다. 실패 원인은 접근/robots/HTTP/화면 렌더링/충돌/명시 날짜 없음/요청 예산 대기 등으로 표시합니다. 원문 전체나 인증값은 진단 보고서에 저장하지 않습니다.

참가 신청·장학금·환불 일정을 섞는 사례를 수정했습니다. `overrides.json`은 관리자 확인 근거가 있을 때만 적용합니다. 자동 값도 보관해 보정을 지우면 복원할 수 있고, 자동 원문에서 날짜가 달라지면 보정 재검토를 표시합니다. 공개 파일에는 공개 공고 정보만 넣습니다.

## 3. 공고와 대회 구분

같은 공식 대회 ID/주소 또는 일치하는 제목·주최·연도·기간 등 확실한 근거를 사용합니다. 서로 다른 연도·차수·부문·공식 대회 ID는 합치지 않습니다. 애매한 제목 유사도만으로 합치지 않습니다. 공고 원본 기록과 ID는 그대로 보관하고 행사 그룹만 추가합니다. 그룹이 바뀌어도 관심 공고의 옛 ID를 연결할 수 있도록 별칭을 보관합니다.

예시(가상): 어제 알던 대회를 오늘 다른 플랫폼에서 다시 발견하면 **새 공고 1건 / 새 대회 0개 / 재게시 1건**입니다. 새 행사 공고 하나와 기존 행사 재게시 하나를 찾으면 **새 공고 2건 / 새 대회·프로그램 1개**입니다. 실제 발표일이나 세상의 모든 신규 대회를 뜻하는 숫자가 아닙니다.

어제 기준이 없거나 오늘 수집이 없으면 정확한 비교 날짜/상태를 표시합니다. 날짜가 바뀌면 오래된 ‘신규’ 강조와 신규 필터를 그대로 유지하지 않습니다. 마감일 변경 전후를 별도로 표시하며, 파서 버전 변경으로 날짜를 새로 읽은 것은 공식 마감 연장으로 단정하지 않고 **추출 정정**으로 구분합니다. 날짜 비교로 추정한 연장은 원문 확인을 요구합니다.

## 4. 분야·관심·설정

행사 종류(대회/프로그램/기타)와 기술 분야(데이터 분석/모델 개발/서비스 개발/AI 영상·디자인/일반 AI)를 독립적으로 선택합니다. 여러 분야가 함께 해당할 수 있습니다. 저장된 제목·주제 등으로 분류하므로 잘못 분류되거나 빠지는 공고가 있을 수 있습니다.

브라우저에 관심 목록과 검색·필터·정렬을 저장합니다. 개인정보를 서버로 보내지 않으며 JSON 내보내기·가져오기로 직접 옮길 수 있습니다. 가져오기는 크기·개수·형식·허용 필드를 검사하며, 기존 관심 목록과 합치고 필터는 파일의 설정으로 바꿉니다. 브라우저 데이터 삭제/시크릿 창/기기 변경에는 자동으로 이어지지 않습니다. 관심 공고 최대 1,000개, 가져오기 최대 256KB입니다.

‘관심 마감 임박’은 본인 기기의 관심 공고 중 확인된 7일 이내 마감입니다. 기본 마감 여유순을 바꾸지 않습니다. 관심 전용 클라우드 알림·회원가입·기기 자동 동기화는 제공하지 않습니다.
