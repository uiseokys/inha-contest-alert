# 디자인 적용 기준 — 공모전 모아보기 v3

## 1. Context and goals / 맥락과 목표
사용자가 첨부한 `SKILL.md`, `DESIGN.md`의 토큰·접근성 지침을 바탕으로 공고 탐색 화면을 정돈하고 일별 변화를 보여준다. 원문은 `design-reference/`에 보관한다.

두 문서는 엘리스의 문서 사이트 맥락을 추출한 지침이며 `DESIGN.md`는 브랜드/대상 추론 신뢰도가 낮다고 명시한다. 완성된 화면 시안이나 특정 사이트를 그대로 재현하라는 자료가 아니다. 따라서 **제품 이름은 기존 ‘공모전 모아보기 / CONTEST MONITOR’를 유지**하며 엘리스 로고·공식 서비스라는 인상을 추가하지 않는다. 외부 브랜드 사이트의 디자인을 가져오지 않았다.

## 2. Design tokens and foundations / 토큰과 기반
### 자료에서 유지한 값
- 글꼴 우선순위: Pretendard Variable, Pretendard 및 제공된 시스템 폴백 계열. 16px 기본 글자, 500 기본 두께, 24px 기본 행 높이.
- 크기: 12 / 13 / 14 / 15 / 16 / 18 / 20 / 24px. 제목도 이 범위에서 선택한다.
- 색: primary `#191f28`, secondary `#212121`, tertiary `#ffffff`, inverse `#343e4b`, surface.base `#000000`.
- 간격: 4 / 5 / 7 / 8 / 10 / 11 / 12 / 15px.
- 곡률: 4 / 6 / 8 / 10 / 50px. 움직임 토큰: 150 / 250 / 300ms.

### 구현을 위해 추가한 역할 — 원문 값과 구분
원문은 어두운 텍스트 토큰과 검정 바탕을 함께 나열하지만 이 둘을 어떤 컴포넌트에 대응시키는지는 정하지 않는다. 읽기 어려운 검정 바탕+어두운 글자를 적용하는 대신 다음처럼 **역할을 배정**했다.
- 검정 surface.base + 흰 tertiary: 데스크톱 탐색 영역과 신규 요약 카드.
- 흰 content 표면 + primary/secondary/inverse 텍스트: 공고 카드와 본문.
- canvas `#f6f7f8`, subtle `#f0f1f3`: 배경과 상세정보 구분.
- muted `#535b66`, on-dark-muted `#c4c8ce`: 보조 문구.
- border.subtle `#dde0e4`(장식 구분선), border.control `#858b93`(입력 경계), border.dark `#40464e`(장식).
- 추가 글자 두께 600 / 700: 제목·강조만 사용.
- 큰 여백은 제공 간격의 2배·4배·5배로 파생한 16 / 24 / 30 / 40 / 48px. 조작 영역은 11px×4=44px.
- 레이아웃 최대 폭, 탐색 영역 폭, 680/960/1200px 분기점은 이 프로젝트의 반응형 배치를 위한 추가 값이다.

CSS 컴포넌트는 **must** 의미 기반 변수만 사용한다. 원시 색상은 `:root` 정의에만 둔다. Noto Sans CJK KR 폴백을 더하되, 서체 파일은 배포물에 포함하지 않는다. Pretendard가 기기에 없으면 시스템 글꼴로 표시된다. 외부 폰트 CDN·유료 서비스·추가 API 호출을 넣지 않는다.

## 3. Component-level rules / 구성·상태·반응형
| 구성 | 기본 / hover / focus-visible / active | disabled / loading / error | 반응형·긴 내용 |
|---|---|---|---|
| 탐색 링크 | 숫자+명확한 이름; hover 표면 변화; 3px 대비 포커스; 현재 위치 `aria-current` | 비활성 버튼인 척하는 가짜 링크 금지. GitHub 주소 없으면 숨김 | 데스크톱 세로 탐색, 960px 이하 상단, 작은 화면 3개 메뉴 |
| 신규 요약 버튼 | 신규 수·단위·기준; hover 배경; keyboard focus; 누르면 신규 목록+체크박스에 초점 | 기준 없음/실패/0건은 disabled. 수집 실패는 숫자 0 대신 ‘—’ | 4열 → 2열. 숫자와 단위 분리 |
| 검색·선택·토글 | label, 입력 경계, 키보드 조작, focus-visible, 선택 상태 표시 | 비교 기준 없으면 신규 토글 비활성. 새 자료 수집은 페이지 로딩과 구분 | 작은 화면 입력 글자 16px, 출처/상태 2열, 정렬 전체 폭 |
| CSV 버튼 | 현재 필터 결과 저장; hover·focus·active | 결과가 없으면 disabled | 44px 조작 높이, 설명 있는 이름 |
| 공고 카드·링크 | 출처/상태/제목/접수기간/기한/원문; 원문 화살표에 대회명이 포함된 aria-label | 누락 정보는 ‘미확인’, 실패는 명시. 추측 링크 금지 | 2열 → 1열. 긴 제목·URL은 숨기지 않고 줄바꿈 |
| 상세 패널 | native details/summary; Enter/Space; 열림 ‘접기’·닫힘 ‘펼치기’; +/− 표시 | 항목별 미확인·과거 정보 잔존 안내 | 날짜와 행사 일정 분리; 링크는 줄바꿈, 내용 자연스럽게 확장 |
| 출처 상태 | 이름과 원문 링크, 정상/부분 실패/실패 문구 | 실패를 ‘공고 없음’으로 취급 금지 | 2열 → 1열. 상세 접근 실패와 목록 실패 구분 |
| 빈 상태·로딩 | 읽을 수 있는 안내, 초기화 버튼, 검색으로 포커스 복귀 | 초기 로딩 `role=status`; JS 미실행 안내 `noscript` | 오류·빈 상태를 단순 공백으로 만들지 않음 |

해당하지 않는 상태는 **must** 임의로 꾸며내지 않는다. 예: 정적 링크에는 네트워크 로딩 상태가 없다. 상태를 정의하지 않은 상호작용을 추가해서는 안 된다.

## 4. Accessibility / 검증 가능한 기준
- 본문 바로가기 링크는 **must** 첫 Tab으로 접근 가능하며 Enter 후 main으로 초점 이동한다. 비활성 링크는 화면 밖 스크린샷에서도 드러나지 않도록 클리핑한다.
- interactive 요소는 **must** 키보드 focus-visible 표시를 가진다. 마우스 클릭 뒤 programmatic focus와 키보드 focus-visible은 다르다.
- 일반 텍스트 대비는 **must** 테스트한 역할 조합에서 4.5:1 이상, 입력 경계는 3:1 이상이다. 전체 사이트 WCAG 인증을 의미하지는 않는다.
- 클릭 타깃은 **should** 44px 조작 영역을 제공한다. checkbox의 label도 조작 영역이다.
- 새 탭 원문 버튼은 **must** 대회명을 포함한 접근 가능한 이름을 가진다.
- 320 / 390 / 768 / 1280 / 1600px에서 **must** 가로 화면 넘침 없이 작동한다. 긴 텍스트와 열린 상세 패널도 포함한다.
- 움직임 감소 설정 시 **must** 전환과 애니메이션을 제거한다.
- 상태는 **must** 색상만이 아니라 텍스트로 구분한다. 결과 건수 변경은 `aria-live=polite`로 전달한다.

## 5. Content and tone / 문구 기준
기능과 사실을 직접 말하고 과장하지 않는다.
- 사용: ‘어제 대비 신규 3건’, ‘새로 확인한 공고 주소 기준’, ‘첫 저장 후 다음 날부터 비교’.
- 사용: ‘2026-09-19 대비 신규 3건 — 어제 기록 없음’, ‘수집 실패로 비교 불가’.
- 금지: ‘새 대회가 정확히 3개 개최됨’, ‘모든 대회를 실시간 확인’, ‘어제 수집 실패 → 신규 0건’.
- 접수기간과 대회기간은 **must** 별도로 표시한다. 불명확한 날짜·자격·상금은 원문 확인 문구를 사용한다.

## 6. Anti-patterns and migration / 금지·이전
- 원문에 없는 보라색/마케팅 표현/엘리스 상표를 자료에서 추출된 내용인 것처럼 도입하지 않는다.
- 전체 건수의 증감을 신규 건수로 대체하지 않는다. 첫 수집을 수백 건의 신규 공고로 표시하지 않는다.
- v2 state를 지우거나 config, workflow, ntfy Secret을 바꾸지 않는다. 하루 기록은 수집 시 별도 키에 추가한다.
- 자료의 ‘links 120, lists 14, buttons 11, navigation 2’는 원 사이트의 관찰 밀도이지 이 프로젝트에 가짜 링크를 추가하라는 할당량이 아니다.
