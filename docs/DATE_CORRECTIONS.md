# 원문 근거를 남기는 관리자 날짜 보정

자동 추출을 기다리기 어려운 중요한 공고에만 사용합니다. **확인하지 않은 날짜를 넣는 기능이 아닙니다.** 예시 파일 `examples/overrides.example.json`은 형식 설명용이며 자동 적용하지 않습니다.

## 적용

저장소 맨 위에 `overrides.json`을 만듭니다. 아래 URL·날짜·근거는 모두 가상입니다. 실제 저장된 **공고 원문 URL**을 키로 사용하고 확인한 값을 입력합니다.

```json
{
  "version": 1,
  "entries": {
    "https://example.org/contests/EXAMPLE-ONLY": {
      "registration_start": "2026-09-01",
      "deadline": "2026-10-31",
      "deadline_time": "18:00",
      "evidence_url": "https://example.org/contests/EXAMPLE-ONLY/update",
      "checked_at": "2026-09-23",
      "reason": "공식 수정 공지에서 접수 마감 일시를 확인함 — 가상 예시"
    }
  }
}
```

시작일을 모르면 `registration_start`를 넣지 않고, 시각을 모르면 `deadline_time`을 넣지 않습니다. 기존의 잘못된 시각을 명시적으로 지우려면 `"deadline_time": null`을 사용합니다. 시작 시각은 선택 항목 `registration_start_time`입니다. 시각은 유효한 `HH:MM`(또는 다음 날 자정을 뜻하는 `24:00`)만 받습니다. 날짜는 `YYYY-MM-DD`입니다.

`evidence_url`, `checked_at`, `reason`은 필수입니다. 확인일은 실제 확인한 날이며 미래 날짜를 넣으면 거부합니다. 역전된 접수 기간이나 잘못된 날짜도 거부합니다. 오류가 있으면 기존 상태를 임의로 초기화하지 않습니다. 비밀번호·ntfy 토픽·개인정보는 이 공개 파일에 넣지 않습니다.

파일 저장 후 **Daily contest dashboard → send_today 체크하지 않고 실행**하면 적용됩니다. 카드의 날짜 근거에서 관리자 보정과 원문을 확인합니다. 행사 통합 카드의 경우 연결된 원본 공고 중 하나의 저장 URL에 적용합니다. 모든 원본 날짜가 같다는 뜻은 아닙니다.

## 변경·제거

자동 수집 날짜와 보정값을 함께 보관합니다. 자동 수집 날짜가 나중에 바뀌면 **재검토 필요**를 표시하고 사람의 보정을 조용히 덮어쓰지 않습니다. 새 원문을 읽고 값·근거·확인일을 갱신하세요. 보정 항목을 지우고 다음 수집을 실행하면 보존한 자동 값으로 돌아갑니다. `data/state.json`을 직접 지울 필요는 없습니다.

진단 보고서는 관리자 보정 포함 확인율과 자동 추출 확인 수를 따로 표시합니다. 보정으로 숫자가 늘어도 자동 추출 성공률이 좋아진 것처럼 설명하지 않습니다.
