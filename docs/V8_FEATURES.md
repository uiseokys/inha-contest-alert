# v8 기능과 보안 경계

## 구현 목록
1. 누적 코드 배포, release-manifest SHA-256/필수 파일 검사, push/PR 검증, 상태 보존, 코드 누락 명확한 진단.
2. 기존 일정/본문 규칙 유지 + 동일 호스트 직접 PDF/HWPX/TXT의 텍스트 확인, 날짜 추출 근거, 이전 표본과 확인율 급락 비교.
3. 라벨 근거를 가진 참가 조건과 독립 필터, 불확실 항목 기본 포함.
4. 브라우저 진행 상태/메모/할 일 + 별도 제출 일정 + 일회성 ICS 내보내기.
5. 명시적 동의로 공개 공고 ID/분야만 서버 반영, 하루 한 번 관심 우선 요약, 과거 시각 일정 제외.
6. 페이지 공고 추가/제목·기간 수정 및 일반 정보 신고. 소유자 확인 이슈만 쓰기 허용.
7. 페이지 HH:MM 시각 선택 → GitHub 소유자 인증/제출 → 서버 설정 저장 → 새 페이지 배포. 익명 방문자가 변경할 수 없음.

## 파일 책임
- settings.py: 비밀이 아닌 서버 설정 스키마와 당일 스케줄 판정.
- intake.py: 구조화 요청 검증, 근거 입력, 소유자 처리 후 상태 반영.
- tools/handle_request.py: GitHub 이벤트와 로그인 actor 검증.
- tools/preflight.py, build_release.py: 누적 파일 묶음과 누락/혼합 버전 점검.
- attachments.py: 동일 호스트·공개 IP·robots 확인, 다운로드5MB, 리다이렉트4회 이내. 추출 프로세스 메모리512MB/CPU8초/대기12초. PDF20페이지, HWPX200개 항목·총8MB 한도.
- participation.py: 참가 자격과 제출 일정의 근거 추출.
- alerts.py, briefing.py: 확인율 경고와 관심 우선 일일 요약.
- web/planner.js, features.js: 로컬 개인정보 저장과 서버에 보낼 공개 요청을 분리.

## 중요한 제한
- 이슈 자동 적용은 개인 GitHub 저장소의 Owner 계정에 한정. 조직 멤버 권한 일반화는 구현하지 않았음.
- 시간/관심 설정은 공통 ntfy 채널 단위. 개별 방문자별 개인 채널 생성은 없음.
- 저장소 자체는 공개이므로 제목·공고 ID·설정 시각·근거·신고 내용도 공개. 주민번호·연락처·토큰·비공개 연구자료를 입력하면 안 됨.
- 임의 URL을 서버에서 곧바로 방문하지 않음. 직접 추가 정보는 사람이 확인한 수동 카드. 수집 사이트를 더 추가하려면 별도 수집기 검토가 필요.
- 텍스트 추출은 OCR이 아님. 이미지·구형 HWP·암호문서·20페이지 초과PDF·중계형 다운로드·외부 CDN 첨부는 미확인 가능.
- 날짜별 발송의 중복 방지를 우선. 예약 후 끄거나 바꿔도 이미 제출된 ntfy 예약 취소는 없음.
- 기존 합성 테스트 + 실제 로컬 PDF/HWPX/TXT 추출/브라우저 이벤트 검사. 원격 GitHub 실행과 실사용 휴대폰 수신은 이번 제작 환경에서 수행하지 못함.
